Pipeline

How it works

Every frame travels the same seven steps. The browser handles capture and display, while all recognition happens in Python on the backend.

01

Webcam capture

The browser asks for camera access and draws frames to a hidden canvas. Each frame is encoded as JPEG and posted to the backend. The browser holds one frame at a time and the server discards it once the prediction returns.

02

Square crop

The widescreen frame is cropped to a centred square by center_square_crop(). This matters more than it sounds. MediaPipe scales x by frame width and y by frame height, so a 16:9 frame stretches the hand horizontally compared with the 200 by 200 training images. Without this step every feature is displaced and accuracy collapses.

03

Hand landmarks

The MediaPipe HandLandmarker locates 21 joints: the wrist, plus four points along each finger. Each carries an x, y and z coordinate, so one hand is described by 63 numbers.

04

Normalization

Raw coordinates depend on where the hand sits in frame. Each landmark is re-centred on the wrist and divided by the wrist to middle knuckle distance, which makes the features invariant to position and distance. The same letter then produces the same numbers near or far.

05

Random Forest classification

The 63 features are standardised and passed to a 200 tree Random Forest that votes across 26 letters. It returns the winning letter and the share of trees that agreed, which becomes the confidence score.

06

Temporal smoothing

A held sign spans many frames, so a single frame is weak evidence. Predictions enter a rolling window and a letter is committed only when at least 4 of the last 5 frames agree and clear the confidence threshold. Losing the hand for several frames resets the window, so reacquiring it cannot inject a spurious letter.

07

Text and audio output

Committed letters append to the transcript. With speech enabled, each new letter is read aloud using the browser's own speech synthesis.

Model information

What the classifier is, how it was measured, and where it falls short.

97.9%

Offline test accuracy

Held out split of the public ASL Alphabet image dataset, 1,143 samples never seen in training. This is a dataset result and not a webcam result. Live accuracy is lower.

0.97

Macro F1

Each letter weighted equally, so weak classes are not hidden behind strong ones.

26

Classes, 63 features

A to Z, each from 21 landmarks by 3 coordinates, trained on 5,712 samples extracted from the public dataset.

Limitations we know about

M and N confusion

The two signs differ only by whether the thumb tucks under two fingers or three, and the thumb is hidden in both. The landmark model infers its position rather than seeing it, so the two letters sit very close together in feature space. On a webcam, N is frequently read as M.

Webcam against dataset

The training images were captured under consistent lighting at a fixed distance. Your camera, lighting and hand will differ, so expect noticeably lower accuracy than the offline figure above.

Detection depends on hand size

MediaPipe needs the hand to occupy a reasonable share of the frame. If letters stop registering, move closer to the camera.

Static letters only

J and Z involve motion in real ASL, but here they are treated as fixed poses. Words and continuous signing are out of scope.
